# GAME.md

## Game Concept
2000년대 초중반 Windows XP 시대를 연상시키는 가상의 PC와 인터넷 환경에서 진행되는 PC 인디 공포게임.

플레이어는 대기업의 외주 디지털 보안·정보정리 담당자로 일하며 온라인에 퍼진 기업 관련 정보의 수정·삭제 업무를 수행한다. 처음에는 합법적인 개인정보 보호·기밀 유출 대응처럼 보이지만, 조사 범위가 넓어질수록 기업이 숨기는 사건과 연구의 흔적을 발견하게 된다.

게임 화면의 대부분은 가상의 컴퓨터 화면으로 구성되며, 실제 Windows XP·Internet Explorer를 그대로 복제하지 않는다.

## Genre
- Horror
- Desktop / Computer Interface Horror
- Internet Investigation Adventure
- Investigation / Mystery
- Retro Web Horror

## Player Role
대기업과 계약한 외부 디지털 보안·정보정리 담당자.

표면적인 업무:
- 기업 기밀 유출 자료 제거
- 개인정보 삭제
- 허위 게시물 정리
- 내부 자료 유출 대응
- 이미지 수정 및 삭제
- 기업에 불리한 온라인 정보 정리

플레이어는 기업 내부자가 아니라 외부 계약자이며, 기업의 관리 범위에 있는 업무용 PC 환경과 S-LINK를 통해 의뢰를 처리한다.

플레이어가 외부 웹사이트를 임의로 수정·삭제하는 것이 아니라, 조사로 대상을 찾아 등록한 뒤 S-LINK에서 해당 의뢰에 허용된 처리를 실행한다.

## Core Experience
플레이어가 인터넷을 직접 탐색하고 단서를 비교하면서 "왜 이 자료를 지우라고 하는가?"를 스스로 판단하게 만드는 경험.

각 Chapter는 단순한 자료 열람이 아니라 다음 흐름을 가진다.

조사 질문
→ 여러 출처의 증거 확인
→ 증거 비교
→ 플레이어의 판단
→ 처리 대상 확정

공포의 정보 공개 순서는 다음을 우선한다.

이상함 → 불편함 → 의심 → 이해 → 공포

기업의 진실은 긴 설명문이나 단일 문서로 제공하지 않고, 서로 다른 사이트·게시물·이미지·기록의 일치를 통해 이해하게 한다.

## Core Gameplay Loop
기업 의뢰 수신
→ 검색어 또는 초기 단서 확인
→ 이번 의뢰의 조사 질문 확인
→ 인터넷 검색
→ 여러 웹사이트 탐색
→ 게시물·댓글·이미지·영상 조사
→ 닉네임·파일명·코드·차량·화물 정보 등 비교
→ 플레이어가 자료 간 관계 판단
→ 처리 대상 등록
→ 지정된 정보 수정 또는 삭제
→ 작업 완료 보고
→ 다음 의뢰 또는 제한된 추가 접근

접근 권한 상승은 항상 신뢰 상승을 뜻하지 않는다. 후반의 추가 권한은 특정 업무 수행을 위한 한시적·제한적 권한일 수 있다.

## Player Actions
- 메일 및 의뢰 확인
- 검색어 입력
- 검색 결과 비교
- 웹페이지 이동
- 게시물·댓글 읽기
- 스크롤
- 링크 추적
- 닉네임·파일명·기업명·프로젝트 코드 재검색
- 이미지 및 원본 확인
- 동일 자료·차량·화물·코드 비교
- 필수 단서와 선택 단서 조사
- 처리 대상 판단 및 등록
- 지정 정보 수정
- 지정 자료 삭제
- 완료 보고

새로운 대형 시스템을 계속 추가하지 않고, 위 행동을 Chapter마다 다른 조사 질문에 재사용한다.

## Investigation / Search Structure
검색엔진을 중심으로 서로 다른 가상 웹서비스가 연결된다.

기본 구조 예시:

뉴스 기사
→ 댓글 작성자 닉네임
→ 닉네임 검색
→ 과거 게시물
→ 개인 홈페이지
→ 사진
→ 사진 속 코드·차량·시설 단서
→ 기업 또는 하청업체 자료

각 Chapter에는 최소 하나의 명확한 조사 질문을 둔다. 플레이어는 제시된 링크를 순서대로 읽는 것이 아니라, 서로 다른 출처에서 확인한 정보가 같은 대상이나 사건을 가리키는지 판단해야 한다.

### 필수 단서
다음 Chapter 또는 현재 의뢰의 결론을 이해하는 데 반드시 필요한 사실.

필수 경로만 따라가도 이후 대사와 사건을 이해할 수 있어야 한다.

### 선택 단서
필수 사실의 정서적 무게, 인물의 상황, 기업의 태도, 사건의 세부 맥락을 강화하는 자료.

선택 단서만으로 후반 핵심 진실을 조기에 확정하지 않는다.

검색 결과, 작성자 닉네임, 이미지 파일명, 업로드 시간, 댓글, 사진 배경, 문서 코드, 화물 식별 정보 등이 다음 탐색의 단서가 된다.

## Edit / Delete Mechanics
삭제와 수정은 단순한 UI 기능이 아니라 스토리의 핵심 행위다.

기본 처리 유형:
- 개인정보 비식별화
- 게시물 일부 수정
- 이미지 원본 삭제
- 확인된 재업로드 삭제
- 지정 자료 삭제

플레이어의 권한 경계:
1. 플레이어는 외부 사이트를 자유롭게 조작하지 못한다.
2. 플레이어가 조사하여 처리 대상 URL·파일·기록을 S-LINK에 등록한다.
3. S-LINK는 해당 의뢰에서 허용된 처리만 실행한다.
4. 요청 범위를 초과한 삭제는 초반부터 제한된다.
5. 기업의 처리 능력은 인터넷 전체에 대한 절대적 통제가 아니라, S-LINK에서 승인된 대상과 기업이 관리할 수 있는 업무·계약 관련 기록에 한정된다.

Chapter 1의 기본 규칙:
- 게시물 본문에 노출된 직원 실명은 비식별화한다.
- 개인정보가 포함된 사진은 PicBox 원본과 확인된 재업로드를 삭제한다.
- TalkBoard의 사진은 PicBox 원본을 불러오는 형태이므로 원본 삭제 후 이미지가 사라진다.
- 별도로 확인된 재업로드는 각각 처리 대상에 등록해야 한다.

Chapter 4~5에서는 조사와 처리 실행을 구분한다. 플레이어는 업무 접근을 유지하기 위해 회사가 지정한 최소 처리 범위만 완료하고, 그 과정에서 확인한 코드·연결 정보로 범위 밖 조사를 이어간다. 추가 삭제를 자발적으로 확대하지 않는다.

후반에는 이 규칙이 역전되어, 기업이 플레이어의 업무 계정·계약 기록·검색 로그 등 관리 범위 안의 흔적을 처리 대상으로 등록한다.

## Progression / Access Level
현재 확정된 진행:
- Chapter 1: External Contractor — Level 1
- Chapter 2: Level 2
- Chapter 3: Level 3
- Chapter 4: Research Leak Response
- Chapter 5: 일시적·업무 한정 Level 4
- Chapter 6: 접근 등급 표시 없음

의미:
- Chapter 1~3: 정상적인 외주 업무 범위 확대
- Chapter 4: 유출 자료 정리를 위한 특수 업무 권한
- Chapter 5: 신뢰 상승이 아니라 특정 거래 자료 정리에 필요한 한시적·제한적 권한
- Chapter 6: 기존 권한 체계에서 제외되고 처리 대상이 된 상태

기업은 플레이어의 모든 인터넷 활동을 볼 수 있는 것이 아니다. 감시는 기업이 관리하는 업무용 PC 환경, S-LINK 사용 기록, 해당 환경에서 발생한 검색·열람 로그를 중심으로 이루어진다.

Chapter 4의 `R-12` 차단은 웹페이지 자체 차단이 아니라 업무 환경에서의 검색어·검색 경로 제한이다. 이미 확보한 직접 URL은 페이지 자체가 삭제되지 않은 경우 접속할 수 있다.

## Horror Direction
점프스케어보다 컴퓨터 인터페이스 자체의 이상 현상을 우선한다.

주요 방향:
- 삭제했던 이미지가 검색 인덱스·캐시 잔여로 잠깐 다시 나타남
- 검색 결과 수가 실시간으로 줄어듦
- 특정 검색어가 업무 환경에서 차단됨
- 업무 범위 밖의 검색 기록이 S-LINK에 표시됨
- 기업 담당자의 말투와 서명이 변함
- 플레이어의 업무 계정·메일·계약·검색 기록이 하나씩 사라짐
- 플레이어가 누르지 않은 자동 처리가 시작됨

Chapter 1의 삭제 이미지 재등장은 기업이 FindOn 전체를 통제한다는 뜻이 아니라, 삭제 직후 남아 있는 검색 인덱스·캐시 잔여처럼 보이게 연출한다. 정확한 기술 설명은 플레이어에게 직접 제공하지 않는다.

아날로그 호러 요소는 게임 바깥의 필터가 아니라 게임 속 콘텐츠로 사용한다.

사용 가능 콘텐츠:
- CCTV
- 캠코더
- VHS
- 연구 기록 영상
- 사내 교육 영상
- 방송 녹화본
- 오래된 JPEG

고어 자체를 공포의 중심으로 사용하지 않는다.

## Visual Direction
- 2000년대 초중반 PC·웹 환경을 연상시키는 Retro Web 분위기
- Windows XP 시대의 감각을 참고하되 실제 OS·브라우저 UI를 그대로 복제하지 않음
- 가상의 OS, 브라우저, 검색엔진, 메신저, 웹사이트 사용
- 게임 화면 대부분을 컴퓨터 화면으로 구성
- 오래된 웹디자인, 저해상도 JPEG, 당시 인터넷 서비스의 분위기를 활용
- CCTV·VHS·캠코더 등은 웹에서 발견하는 콘텐츠 내부에 사용

정확한 색상 팔레트, 폰트, 화면 해상도, 가상 OS 명칭은 미정.

## UI Direction
UI는 단순한 메뉴가 아니라 게임 세계 그 자체다.

핵심 원칙:
- 검색, 메일, 게시판, 개인 홈페이지, 이미지 호스팅, 기업 업무 시스템이 하나의 인터넷처럼 연결되어 보여야 함
- 실제 서비스 복제보다 당시 인터넷 사용 경험을 재구성하는 방향
- 초반 UI는 정상적이고 기능적으로 보이게 유지
- 후반으로 갈수록 접근 제한, 사라지는 데이터, 비정상 상태 메시지 등으로 UI 자체가 적대적으로 변화
- 플레이어에게 필요한 정보는 가능한 한 실제 화면과 콘텐츠 안에서 전달
- 영화식 컷신보다 클릭·검색·스크롤·읽기·비교·삭제 중심 진행

게임 초반 계약·업무 환경 확인 과정에서 다음 정보를 자연스럽게 노출한다.
- 업무용 이메일
- 계약 날짜
- 업무 ID
- 현재 사용자 이름

이 정보는 Chapter 6에서 삭제 대상이 플레이어 자신임을 확인하는 비교 기준으로 재사용한다.

## Audio Direction
사운드는 인터페이스의 현실감과 불편함을 강화하는 방향으로 사용한다.

현재 확정된 예시:
- PC 부팅음
- 메일 알림음
- 키보드 입력음
- HDD/로딩 계열 소리
- 웹페이지 로딩음
- UI 선택·완료음

첫 이상 현상처럼 일부 공포 연출은 의도적으로 별도 효과음을 사용하지 않는다.

BGM 사용 여부, 음악 스타일, 구체적인 사운드 팔레트는 미정.

## Must Preserve
1. 인터넷 검색과 탐색이 게임의 중심이다.
2. 플레이어가 직접 단서를 따라가고 자료 간 일치를 판단한다.
3. 삭제·수정 행위가 스토리와 직접 연결된다.
4. 각 Chapter는 최소 하나의 조사 질문을 가진다.
5. 기업의 비밀을 한 번에 설명하지 않는다.
6. 플레이어가 단서를 연결해 진실을 이해하게 한다.
7. 필수 단서는 다음 진행에 필요한 사실, 선택 단서는 정서와 맥락 강화에 사용한다.
8. 분위기와 인터페이스 연출을 중요하게 취급한다.
9. 2000년대 인터넷 특유의 분위기를 유지한다.
10. 고어만으로 공포를 만들지 않는다.
11. 검색 → 읽기 → 삭제의 단순 반복을 피한다.
12. 적은 게임 시스템을 다양한 상황에 재활용한다.
13. 마지막에 플레이어 자신이 삭제 대상이 되는 구조를 유지한다.
14. 플레이어가 과거 피해자의 흔적을 직접 지웠다는 사실이 후반에 재해석되어야 한다.
15. 기업의 감시·삭제 능력은 설정된 관리 범위를 넘는 전능한 시스템으로 표현하지 않는다.
16. 1인/소규모 저예산 개발 규모를 유지한다.

## Must Avoid
- 실제 Windows XP·Internet Explorer의 직접 복제
- 레퍼런스 게임의 UI 배치·스토리·진행 구조 복제
- 링크를 정해진 순서대로 열기만 하면 결론이 나오는 Chapter 구성
- 긴 설명문 하나로 모든 진실 공개
- 매 Chapter 동일한 검색 → 무서운 글 → 삭제 반복
- 선택 단서를 보지 않으면 이후 필수 스토리를 이해할 수 없는 구조
- 선택 단서에서 후반 핵심 진실을 너무 일찍 확정하는 구조
- 점프스케어 중심 공포
- 고어만으로 충격을 만드는 전개
- 불필요하게 많은 웹사이트·NPC·시스템 추가
- 구현 비용이 큰 기능을 스토리 해결책으로 계속 추가
- 기업이 인터넷 전체와 플레이어의 모든 개인 기기를 자유롭게 조작할 수 있다는 설정
- 기업을 처음부터 노골적인 악당으로 표현
- 연구의 시작부터 인육 생산이 목적이었다는 설정
